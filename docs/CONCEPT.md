# ポップアップコンピュータ再現構想（PopupMaker.next）

> 1990年代のCD-ROM作品「ポップアップコンピューター」の"手ざわり"を、
> 2020年代のWeb技術で再構築するための構想メモ。

---

## 0. 原典について

**『Pop up Computer』**（ポップアップコンピューター）

| 項目 | 内容 | 確度 |
|---|---|---|
| 作者 | **松本弦人**（1961年生、アートディレクター／グラフィックデザイナー） | 確認済 |
| 制作 | **サルブルネイ**（Saru Brunei Co.,Ltd. 松本弦人の制作会社）。デモ冒頭に "SARU BRUNEI presents" のロゴが出る | 確認済 |
| 発売元 | **アスク講談社**（1981年設立。1998年に講談社出資分を買い戻し「アスク」に、2017年アスク出版へ吸収合併） | 確認済 |
| 対応環境 | Macintosh / Windows 3.1 / Windows 95 のハイブリッド | 確認済 |
| 定価 | 4,800円 | 確認済 |
| 形態 | 「飛び出す絵本CD-ROM」を謳ったデジタル絵本 | 確認済 |
| 発売年 | 1995〜1996年頃 | **要確認** |
| 受賞 | マルチメディアグランプリ 通商産業大臣賞、という情報あり | **要確認** |

松本弦人は同時期に、デジタローグから『ジャングルパーク』、後年には任天堂の『動物番長』など、
デジタルメディアのアートディレクションを手がけている。つまり**これはゲーム会社の作品ではなく、
グラフィックデザイナーの作品**である。ここが本質で、再現の指針にもなる
（ゲーム的な設計を足すと必ず壊れる、の根拠）。

一次資料は中古市場（ヤフオク・メルカリに現物の出品あり）と、
文化庁メディア芸術データベースの「アスク講談社」項が当たれる。

### 実機デモ映像の観察ログ（2分57秒・640x480・6fps のデモ版キャプチャ）

推測ではなく、実際の映像から確認できた事実。**ここで従来の想定がいくつか覆った。**

#### 構成（タイムライン）

| 時刻 | 内容 |
|---|---|
| 0:00 | 暗転から棒状のものが立ち上がり、"SARU BRUNEI presents" ロゴ／"sorry this is demo version" |
| 0:18〜 | **赤いハードカバーの本**が黒背景に浮かび、ゆっくり回転しながら開く |
| 0:45 | 見返し（大理石模様）→ 黄色の扉ページ（Saru Brunei ロゴ） |
| 0:48 | **Contents**：極彩色の立体文字が格子状に並ぶメニュー見開き |
| 1:00 | **Apollo**：ロケット発射台のジオラマ（APOLLO / SOYUZ / Vostok） |
| 1:30 | **Beach Walker**：海岸と断崖と雲のジオラマ。Chapter 1 / "Long Long Ago..." の章題と日本語の物語テキスト |
| 2:24 | **Character Maker II**：サル顔のパーツが格子に並ぶキャラクター作成ツール。作ったキャラが立ち上がる |
| 2:45 | **Margaret**：白黒の漫画見開き |
| 2:50 | 奥付ページ → 本が閉じる |

#### 判明した事実と、それによる修正

**1. これはアンソロジーである（＝「紙のOS」構想は的中）**

Contents から Apollo / Beach Walker / Character Maker II / Margaret へ分岐する。
1冊の本が複数のコンテンツを束ねる器になっている。しかも**原典にすでに
「Character Maker II」というメーカー系ツールが入っている**。
本プロジェクトがオーサリングツールを志向するのは、原典の精神から外れていない。

**2. 背景は机ではなく「黒い虚空」**

本は真っ黒な空間に浮かび、上方からの強いライト1灯で照らされる。
机・部屋・生活感は一切ない。演劇の一人舞台のような照明。
→ 旧稿の「机の上のスケール感」は**誤り**。黒バックに浮かせる。

**3. 紙のリアリティを狙っていない**

90年代の3DCGそのもので、フラットシェーディング、原色に近い彩度、
テクスチャらしいテクスチャは見返しの大理石模様くらい。紙の繊維も、
反りも、裏透けもない。**清潔なCGであることが魅力**。
→ 旧稿の「紙に見せるレンダリング指針」は原典再現としては**過剰**。

**4. 物語テキストがある**

Beach Walker は章立てのある読み物。
「〈ぼく〉がまだ〈ぼく〉ではなく、4つの手をつかってジャングルの生活を送っていたころ……」
といった日本語がジオラマの上に白文字で重なる。
→ 旧稿の「目的がない／テキストUIがない」は**言い過ぎ**。無目的なのは操作の話であって、
　　読ませるコンテンツは明確に存在する。

**5. 音は「無音が基底」で正しかった（実測）**

音声を8kHzモノラルに落として1秒窓でRMSを測ったところ、
**176秒中69秒（39%）が完全な無音（デジタルゼロ）**。特に 0:33〜1:02 の約30秒、
Contents メニューを表示している間はまるごと無音だった。
一方 Beach Walker の物語パート（1:30〜2:21）は連続した音が途切れずに鳴っている。

→ **メニューや待機は完全無音、読み物パートには音の床を敷く**、という使い分け。

### 何が良かったのか（再現すべきコア）

| 要素 | 中身 |
|---|---|
| 紙であること | 画面の中のものが全部「紙でできている」。厚みがあり、折れ、影が落ちる |
| 展開する快感 | 開くと立ち上がる。閉じると畳まれる。可逆で、何度でもやりたくなる |
| 目的がない | スコアもクリアもチュートリアルもない。触ると反応する、それだけ |
| 音が主役 | 全てのオブジェクトが固有の音を持つ。BGMではなく「効果音の楽器化」 |
| 世界が小さい | 机の上に収まるスケール感。全体を把握できる安心感 |
| コンピュータのパロディ | 「紙でできたコンピュータ」というメタな見立て |

**この6つを満たせば、絵が違っても"あれ"になる。** 逆に3D的にリッチにしたり、
達成要素を足したりした瞬間に別物になる。

## 1. 三つの方向性と選択

### 案A：保存・エミュレーション（原典を動かす）
- 現物のCD-ROMを入手 → ディスクイメージ化
- Mac版: SheepShaver / Basilisk II（Mac OS 8-9 + QuickTime）
- Win版: 86Box or PCem + Win95/98、あるいは Wine
- 中身はほぼ確実に Macromedia Director のプロジェクタ。`ProjectorRays` 等の
  Director 逆コンパイラで内部構造（キャスト、スコア、Lingo）を読める（要検証）
- **法的**: 自分で買った現物を私的に動かす／構造を調査するのは可。
  イメージやアセットの再配布・流用は不可。

→ **位置づけ：研究フェーズ。作品化ではなく「教科書」として使う。**

### 案B：クローン再制作（絵も含めてそっくりに作り直す）
- 著作権的にアウトに近く、かつ一番つまらない。**却下。**

### 案C：紙のOS（Paper Desktop）— 本命 ★
「紙でできたコンピュータ」という見立てだけを継承し、
**ポップアップ絵本そのものがデスクトップ**である作品を新規に作る。

- 見開き1ページ = 1画面。ページをめくるとアプリが切り替わる
- 時計は回転盤（ヴォルヴェル）、音楽プレイヤーはオルゴール、天気は箱庭ジオラマ
- 全部が実在しうる紙工作として成立する（＝**印刷して実際に作れる**）

→ ここに **PopupMaker**（ポップアップ機構オーサリングツール）を組み合わせる。
　　作品と、作品を作る道具を、同じエンジンで作る。

## 2. 技術的な分岐点：原典は「機構」ではなく「アニメーション」だった

**当初の構想では、ポップアップを「背の開き角 θ を唯一の駆動パラメータとする
1自由度リンク機構」として扱う設計を背骨に据えていた。デモ映像の検証により、
これは原典の説明としては誤りだと判明した。**

### 検証

Apollo の発射台が閉じた状態（1:10）と開ききった状態（1:16）の
フレームを画素単位で比較した。

| 領域 | 平均絶対差 | 30階調以上変化した画素 |
|---|---|---|
| 本体（ページと表紙が写る下部25%） | **0.53** | **0.0%** |
| 上部50%（ガントリー塔が写る領域） | 13.31 | 15.0% |

ページの輪郭線の座標も両フレームで完全に一致（走査線288で左端147・右端495）。
つまり**本はまったく動いていないのに、塔だけが開いている**。

したがって原典の飛び出しは、紙の機構の再現ではなく、
**開いた状態のページの上で再生される独立した3Dアニメーション**である。
実際、Apollo の塔の開き方は紙の折りではなく、
本物の発射台が打ち上げ時に退避する動きをなぞっている。
飛び出している物体自体も紙ではなく、格子構造の塔やロケットという立体物。

**紙なのは本（表紙とページ）だけで、中身は紙ではない。**

### ここが企画の分岐点になる

| | A案：原典の方式 | B案：紙の機構の方式 |
|---|---|---|
| 飛び出しの駆動 | タイムラインを再生 | 開き角 θ から姿勢を算出 |
| 中身の素材 | 何でもよい（立体物・映像） | 剛体パネルとヒンジのみ |
| 表現の自由度 | **高い**。ロケットが飛んでもよい | 紙で作れる範囲に限られる |
| 実現性の検証 | 不要 | 収納性・干渉・糊代の判定が要る |
| 印刷して組み立て | **できない** | **できる** |
| 実装コスト | 低い（glTFのアニメーション再生） | 高い（幾何とソルバを書く） |

**A案は原典に忠実で、作るのは容易。B案は原典とは別物だが、現代に作る意味がある。**

旧稿の θ 駆動の議論は、原典の説明としては撤回する。
ただし B案を採る場合には依然として正しい設計であり、以下は B案のための記述として残す。

### （B案を採る場合）ポップアップ機構の数理

折り線が4本1点に集まる剛体折り紙の頂点は1自由度であり、
隣接する折り角どうしは球面三角法で閉形式に結ばれる。
したがって V字折り・平行折りは θ から解析的に姿勢が決まる。
複合機構は Blender で θ をドライバにして glTF にベイクすれば同じ扱いにできる。

実装する基本機構：

| 機構 | 和名 | 駆動 |
|---|---|---|
| V-fold | V字折り | θ |
| Parallel fold / box | 平行折り・箱 | θ |
| Layer / step | 階段折り | θ |
| Pivot | 回転（リベット） | θ or ドラッグ |
| Pull tab | プルタブ | ドラッグ |
| Volvelle | 回転円盤 | ドラッグ |
| Slider | スライダー | ドラッグ |

**「本当に作れるか」の検証器（Validator）** — θ を 0→π にスイープして数値チェックする。

1. **収納性**: θ=0 のとき、全パネルが見開きの外形からはみ出さないか
2. **貫通判定**: 途中の θ でパネル同士が交差しないか
3. **平坦性**: θ=0 で厚みが破綻しないか（層数の上限）
4. **糊代**: 接着面積が最低値以上あるか

NG のヒンジを赤くハイライトして、直せる範囲を提示する。

### 推奨：A案の見た目でB案の中身を作る

黒背景・1灯・清潔なCGという**原典の様式**を採りつつ、
飛び出す中身は**紙の機構として成立させる**。
こうすると「原典へのオマージュ」と「印刷して作れる」が両立し、
かつA案の弱点（何でもありゆえに締まらない）をB案の制約が補う。
機構カーネルは、この制約を担保する部品として意味を持つ。

## 3. アーキテクチャ

```
┌─────────────────────────────────────────────┐
│  Next.js (App Router) / TypeScript          │
├──────────────────┬──────────────────────────┤
│  Viewer          │  Editor (PopupMaker)     │
│  React Three     │  SVG 2D 型紙ビュー       │
│  Fiber + drei    │  ＋ 3D プレビュー分割    │
├──────────────────┴──────────────────────────┤
│  popup-core (機構カーネル / 依存なし)        │
│   ・Mechanism 定義と θ→姿勢のキネマティクス  │
│   ・Validator（収納性・干渉・糊代）          │
│   ・展開図ジェネレータ（SVG）                │
├─────────────────────────────────────────────┤
│  Web Audio（θ速度に応じた紙擦れ音の粒状合成）│
└─────────────────────────────────────────────┘
```

`popup-core` を **React にも Three.js にも依存しない純粋な TS パッケージ**にするのが肝。
これで CLI からも Node からも叩けて、展開図の一括生成や回帰テストができる。

### シーン記述フォーマット（`.popup` = JSON）

```jsonc
{
  "version": 1,
  "title": "紙のデスクトップ",
  "paper": { "stock": "ケント紙 200g", "size": "A4横" },
  "spreads": [
    {
      "id": "clock",
      "base": { "texture": "paper/kraft.png" },
      "mechanisms": [
        {
          "type": "v-fold",
          "id": "tower",
          "glueAngle": 45,          // 背に対する糊代の角度
          "height": 60,             // mm
          "faces": ["art/tower_a.png", "art/tower_b.png"],
          "sound": { "on": "open", "clip": "sfx/paper_rise.wav" }
        },
        {
          "type": "volvelle",
          "id": "clock-dial",
          "center": [120, 80], "radius": 35,
          "bind": { "target": "time.minutes" },   // 実データに結線
          "sound": { "on": "step", "clip": "sfx/click.wav", "everyDeg": 6 }
        }
      ],
      "hotspots": [ { "at": "tower", "sound": "sfx/boing.wav", "wiggle": 0.3 } ]
    }
  ]
}
```

`bind` で実データ（時刻・天気・カレンダー）に繋げられるのが「コンピュータ」たる所以。

## 4. 見た目の指針（原典の様式に準拠）

デモ映像の観察に合わせて全面改稿。**紙をリアルに見せようとしない。**

- **背景は純黒**。机も部屋も影の落ちる床も置かない。本だけが虚空に浮かぶ
- **ライトは上方から1灯**。これは原典どおりで、旧稿の結論とも一致した
- **フラットに近いシェーディング**。物理ベースレンダリングの質感表現を切る
- **彩度を上げる**。シアン、マゼンタ、黄、朱。中間色でまとめない
- **紙のテクスチャを貼らない**。ページは白〜クリームの無地。
  例外は見返しの大理石模様（原典にあり、ここだけ密度が高くて効いている）
- **本はゆっくり回る**。固定カメラではなく、本自体が回転しながら開く
- **カバーは赤、小口は白、しおりは朱**。原典の配色をそのまま踏襲してよい

紙の繊維・反り・裏透け・網点といった旧稿の指針は、
原典再現としては過剰なので採用しない。**清潔なCGであることが原典の魅力**。
（B案で印刷用の型紙を出す場合も、画面表現は清潔なままでよい）

## 5. 音の設計（実測に基づく）

デモ音声の実測では **176秒中69秒（39%）が完全な無音**、
Contents メニュー表示中は約30秒まるごと無音だった。
一方で物語パートには連続した音の床がある。この使い分けを踏襲する。

- **メニュー・待機・移動中は完全な無音**。環境音すら置かない
- **読み物パートにだけ音の床を敷く**。ここは連続再生でよい
- オブジェクトごとに固有音。近い音程で調律しておくと、触るうちに音楽になる
- 音は必ず触った瞬間に鳴る。遅延ゼロ（Web Audio の事前デコード必須）
- ページをめくる音は角速度でグラニュラー合成（B案を採る場合に有効）

## 6. 実物への出力（ここが現代版の意味）

デジタルで作ったポップアップを **印刷して実際に組み立てられる**。

- SVG / PDF で展開図を出力
  - 実線 = カット、破線 = 山折り、点線 = 谷折り、グレー = 糊代
- Silhouette / Cricut 等のカッティングマシン用にレイヤ分け出力
- 組み立て手順を θ アニメーションから自動生成（逆再生 = 組立順）

**画面の中で作って、机の上に出てくる。** 原典が「紙をコンピュータの中に入れた」作品なら、
こちらは「コンピュータの中の紙を外に出す」作品になる。

## 7. 開発ロードマップ

### Phase 0：調査（1〜2週）
- デモ映像の観察は完了（§0）。次はA案／B案の方針決定
- 現物（中古CD-ROM）を入手し、エミュレーション環境で実際に触る
- 発売年と受賞歴を一次資料で確定させる（§0の「要確認」を潰す）
- 何が気持ちよかったのかを言語化してこのドキュメントを更新

### Phase 1：機構カーネル MVP（2週）
- `popup-core`：V字折り・平行折りの θ キネマティクス＋単体テスト
- ヘッドレスで展開図 SVG を1枚出す（3Dなしで検証できる状態を先に作る）

### Phase 2：ビューア（2週）
- R3F で1見開きを描画、ドラッグでページ開閉、クリックで音
- **ここで「気持ちいいか」を判定する。駄目なら Phase 1 に戻る**

### Phase 3：エディタ（4週）
- 2D型紙ビュー＋3Dプレビューの分割画面、機構の追加/編集、Validator

### Phase 4：作品「紙のデスクトップ」（4週）
- 時計・天気・音楽・カレンダーの4見開き。実データ結線

### Phase 5：実物出力（2週）
- PDF/カッティングマシン出力、組立手順の自動生成

## 8. 技術選定

| 領域 | 採用 | 理由 |
|---|---|---|
| フレームワーク | Next.js (App Router) + TS | リポジトリ名が `.next` |
| 3D | React Three Fiber + drei | 宣言的、R3F のエコシステム |
| 状態 | Zustand | θ を1箇所で持つだけなので軽量で十分 |
| 音 | Web Audio API 直叩き | 低遅延とグラニュラー合成が必要 |
| アセット | Blender → glTF | 複合機構はベイクして持ち込む |
| 型紙出力 | 自前 SVG 生成 | ライブラリ不要 |
| テスト | Vitest（`popup-core` のみ厚く） | 幾何は回帰テストが効く |

## 9. やらないことリスト（重要）

- スコア・実績・レベル・チュートリアル
  （ただし原典には章立ての読み物があった。「無目的」なのは操作の話であって、
  　読ませるコンテンツを置かない理由にはならない）
- ログイン必須化、課金導線
- 物理エンジンによる紙のシミュレーション（重い・不安定・不要）
- 机・部屋・生活感のある背景（原典は黒い虚空）
- 写実的な3D。原典は90年代CGの清潔さが魅力で、質感を作り込むほど遠ざかる
- VR対応（机の上のスケール感が壊れる）

## 10. 法的整理

- 原典のアセット（絵・音・テキスト・フォント）は一切使わない
- 「ポップアップコンピューター」の名称は使わない。別名で出す
- 現物のCD-ROMを自分で買って私的に動かす／構造を調査するのは問題なし
